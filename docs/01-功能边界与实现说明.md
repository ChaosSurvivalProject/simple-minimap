# 功能边界与实现说明

## 唯一允许实现的功能

1. **主界面**：屏幕角落 2D 角标小地图。画面里只允许存在
   - ① 地形色块；
   - ② 玩家自己一个图标（可带朝向）。
   除此之外一个像素都不多画。
2. **按键**：注册 `M` 键；按下只打开「地点标记管理」界面，仅支持添加、重命名、删除标记；它不是第二张地图，不显示地图、坐标面板或任何其他信息；关闭即释放。
3. **迷雾**：地形只显示已探索 / 已加载过的区域，未探索区域留空。
4. **标记**：仅本地用途，不共享、不多人同步。
5. 其余功能一律不要。

## A · Fabric 实现要点

- 入口：`SimpleMinimapClient implements ClientModInitializer`，`fabric.mod.json` 声明 `environment: "client"`。
- 按键：`KeyBindingHelper.registerKeyBinding`，`GLFW_KEY_M`；仅在 `currentScreen == null` 且会话就绪时 `setScreen(new MarkerScreen(session))`。
- HUD：`HudRenderCallback.EVENT.register((context, tickCounter) -> ...)`；官方 Javadoc 签名为 `(GuiGraphics, DeltaTracker)`，Yarn build.6 下对应 `(DrawContext, RenderTickCounter)`。该回调在当前版本已弃用但仍可用，类级加 `@SuppressWarnings("deprecation")`；**不** Mixin `InGameHud`，**不**用 `Screen.render` 伪装。
- 地形色：`MapColor.getRenderColor(MapColor.Brightness.NORMAL)` 直接取游戏内地图色，不自带 256 色表。
- 探索集：区块级访问记录。`ChunkColorSampler` 在玩家所在区块变化时采样 3×3 区块，每区块 256 个 ARGB 色值；`ExplorationStore` 以 `ChunkPos.toLong` 为键。只有已访问区块会被写入，未访问区块查询返回透明，渲染时跳过。
- 存储：`config/simple_minimap/<world-id>/explored.bin` + `markers.json`；所有磁盘 I/O 在单线程守护线程池中完成，渲染线程不读盘；换世界时用 generation 计数丢弃过期加载结果；写入用临时文件 + 原子移动。
- 渲染：64×64 缓存，同一行连续同色合并为一次 `fill`，减少每帧调用；玩家图标为 5×5 像素方块（黑底白心），不含其他元素。
- 标记界面：自定义 `Screen` + `TextFieldWidget` + `ButtonWidget`，仅添加 / 上一个 / 下一个 / 重命名 / 删除；关闭时 `saveAsync()`。

## B · Bedrock 实现要点

- 清单：行为包与资源包均 `format_version: 2`、`min_engine_version: [1,21,130]`，四个 UUID 为本次新生成的 v4；脚本依赖按 `module_name` + `version` 写。
- 模块：`@minecraft/server@2.4.0`（读数、维度、玩家、动态属性、自定义命令）与 `@minecraft/server-ui@2.0.0`（模态表单）。
- 地形：7×7 离散字符网格，每 4 tick 采样一次；`isChunkLoaded` 保证未加载留空；`getTopmostBlock(xz, minHeight)` 取地表；按 `typeId` 前缀映射到 10 色字符调色板；中心 `+` 代表玩家。
- 迷雾：每个区块 256 格颜色下标字符串写入玩家动态属性；缓存键含维度 ID；最多 96 个属性，超出逐出最旧。
- 标记入口：无按键绑定 API，注册 `/simplemap:markers` 自定义命令（`permissionLevel: Any`、`cheatsRequired: false`）；表单仅支持添加 / 重命名 / 删除。
- 存储：标记与探索都在玩家实体动态属性上，按玩家隔离；不共享、不同步。
- 没有 JSON-UI 注入：未新增 `_ui_defs.json` / `hud_screen.json`；不声称官方像素画布或本地文件能力。
