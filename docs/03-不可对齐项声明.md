# 不可对齐项声明（Fabric ↔ Bedrock）

两套实现严格共享同一功能边界，但基岩版平台能力存在客观差距。以下如实列出，不做「已对齐」的虚假宣称。

| 维度 | Fabric（Java 1.21.11） | Bedrock（1.21.130） | 差距代价 |
|---|---|---|---|
| 小地图位置 | 屏幕左上角 64×64 像素色块 | 动作栏（屏幕下方）7×7 离散字符网格 | 位置不在角落；分辨率低两个数量级 |
| 地形取色 | `MapColor.getRenderColor(NORMAL)` 逐像素取游戏内地图色 | 按方块 `typeId` 前缀映射到 10 色字符调色板 | 颜色是近似分类，不等价于 Java 地图色 |
| 探索迷雾 | 区块级访问记录，二进制文件持久化 | 区块级 256 格字符串，玩家动态属性持久化 | 基岩属性有 96 区块上限，超出逐出最旧区块（迷雾回退）；Java 无此硬上限 |
| 玩家图标 | 5×5 像素方块（黑底白心） | 中心 `§f+` 字符 | 均只表示玩家自己，均无其他实体 |
| 标记数据 | 本机 `config/simple_minimap/<world>/markers.json` | 玩家实体动态属性 `simplemap:markers` | 基岩侧无独立本地文件；按玩家隔离，同一存档内不共享 |
| M 键 | `KeyBindingHelper` 注册 `GLFW_KEY_M` | **无按键绑定 API**，改用脚本命令 `/simplemap:markers` | 按键语义无法在基岩原生复现；这是有意偏离 |
| 标记界面 | 自定义 `Screen`（仅添加/重命名/删除） | `ActionFormData` / `ModalFormData`（仅添加/重命名/删除） | 形态不同，功能边界一致 |
| 渲染机制 | `HudRenderCallback`（官方已弃用但仍存在，签名 `(DrawContext, RenderTickCounter)`） | 文本通道 `onScreenDisplay.setActionBar` | 基岩走社区已验证但**非官方稳定能力**的路径 |

## 基岩角标地形的落地路径与风险（必须知悉）

本实现采用任务允许的「actionbar / title 文本通道 + 颜色字符绘制离散地形网格」路径：

- 脚本每 4 tick 采样玩家周围 7×7 格方块；
- 用 `Dimension.isChunkLoaded` 保证未加载区域留空（迷雾）；
- 用 `Dimension.getTopmostBlock(xz, minHeight)` 取地表方块，按 `typeId` 映射颜色字符；
- 中心字符 `+` 固定代表玩家自己；
- 结果整体写入 `onScreenDisplay.setActionBar(...)`。

**代价与限制（不做淡化）**：

1. 依赖未公开的 JSON-UI / 文本通道字符串操作语义；Mojang 并未承诺 actionbar 可作为画布使用。
2. 需要开启 Beta / 实验脚本开关才能运行脚本模块（取决于世界设置与版本策略）。
3. 每个引擎版本都要重新验证：脚本 API、actionbar 行为、字符宽度与颜色码均可能变化。
4. 分辨率明显低于 Fabric 的逐像素色块；字符宽度受字体影响，网格可能对不齐。
5. 不采用 JSON-UI 的 `hud_screen.json` 注入方案：本交付未新增任何 UI 定义文件；若将来采用，必须经 `_ui_defs.json` 声明路径并在 `root_panel.modifications` 中以 `insert_front` 插入带命名空间的控件，不得声称存在官方动态纹理/像素画布。

## 共同遵守的边界

- 主画面只画地形色块和玩家自己一个图标，不画坐标轴、不画坐标数字、不画其他实体。
- 标记界面只做添加 / 重命名 / 删除，不是第二张地图，不显示坐标面板。
- 标记只本地保存，不共享、不同步。
- 除上述功能外不实现任何其他功能。
